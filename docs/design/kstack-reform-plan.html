kstack 项目改造计划

把 aster 的后端模块迁入 kense，统一 k* 命名；aster 不再保留任何后端模块

版本 v1.1 · 已废弃 2026-11-08 范围：只规划，未改动任何仓库代码 关联：unified-ai-platform-architecture.html v0.7

本计划已废弃：方向改为在 kense 用 Rust 自研 kstack 等效能力，运行时、构建与部署都不再依赖 kstack。最终设计见 ai-os-architecture.html v2.0（全 Rust、无前缀职责命名、后端主仓 platform），并已在 platform/ 落地 7 个可编译 crate 骨架。本文的迁移阶段、k* 命名映射与「保留 Go 执行面」前提均已失效，仅作历史记录保留。

一句话目标：kense 成为后端源码的唯一权威，按 k* 命名；aster 退化为纯客户端（CLI / Studio / Web / 官网 / packages / plugins）。本轮只输出计划，未复制、重命名或删除任何代码。

0x00 : 前提与边界

  • kstack 源码不在本机：/Users/roylin/code/kense/kstack 已不存在，仅 /tmp/kstack-e2e/ 留有 5 个 SQLite 运行产物。它是 Go 1.26 的 MaaS 单二进制平台，今早的实证记录已固化在架构蓝图 0x09 / 0x11 / 0x13。改造前须重新检出 kense-labs/kstack，并保持其 Go 执行面独立，不建议把 Rust 后端塞进它。
  • kense 不是单仓：无根 Cargo.toml，是 6 个独立 git 仓（kbox / kcl / kpower / ksandbox / kstudio / kbuddy）+ 根 justfile（只转发到 kbuddy）。各仓自带 Cargo.toml 与 lockfile。
  • aster 是 4 个 workspace：根 workspace（约 180 crate）+ apps/cloud、apps/api、apps/control-plane 三个独立 workspace（根 Cargo.toml 显式 exclude），各带 Cargo.lock；另有 5 个 git submodule 与 5 个符号链接。
  • 「不再保留任何后端模块」的工程解释：aster 不再拥有后端模块的源码权威，但必须保留对 kense 新仓的 git / registry 依赖引用。原因是 apps/studio/src-tauri 有 16 条 path 依赖、apps/aster CLI 有多条 path 依赖指向这些共享库；若字面意义上全部删掉，留下的客户端立即编译失败。此项列为待确认决策 D3。

0x02 : 目标形态

迁移后的仓库组织　/　后端源码权威集中，已有 k* 仓保持独立

建议新建一个后端主仓（暂名 kserve），而不是塞进 kbox 或 kpower —— 后两者有各自的 workspace 与发布节奏，且 kstack 是 Go 执行面，三者混仓会重演 aster 四 workspace 的复杂度。仓内按 crates/（基础库）、contracts/（契约与 OpenAPI）、services/（服务 bin）组织，一个 workspace、一份 Cargo.lock。凭据保管独立为 kvault，不并入 gateway，也不与 Studio 的 knowledge_vault 混淆。

0x03 : 命名规则与完整映射

规则：① 去掉 aster- / aster-use- 前缀，统一 k 前缀（用户示例 aster-boot → kboot）；② 服务端可执行包加 d 或 -svc 后缀，避免与同名 CLI 库冲突；③ 同名异物用限定名区分；④ 线协议字符串值（*_SCHEMA_V1、/v1/... 路径、operationId、tag）一律不改，只改 crate 名与 Rust 标识符；⑤ 已占用名字不复用，已完成迁移的不再新建。

0x06 : 验收标准与明确不做

6.1 完成的定义

  1. aster 根 Cargo.toml 的 exclude 清空（或只剩非后端项），default-members 仅含客户端；root / api / cloud / control-plane 四个 workspace 中不再有任何 server bin 或云侧服务源码。
  2. kserve 单仓拥有全部后端源码权威，每个模块全仓唯一；cargo check --locked --workspace 与 backend.yml 矩阵全绿。
  3. 线协议常量、OpenAPI 快照、CLI/sidecar BUILD_ID 配对与迁移前字节一致。
  4. 新增 CI 门禁能主动拒绝把后端 crate 加回 aster；两仓 tag 通道与 latest.json 互不串味。
  5. kstack（Go）重新检出并保持 MaaS 执行面独立，通过契约与 kserve 交互，不被改名波及。
  6. kvault 具备三层 Scope、sealed / active / revoked 状态机、版本化凭据与可审计 receipt；明文不落日志、审计事件、wire 与沙箱。

6.2 明确不做

  • 不统一语言：kstack 保持 Go，kserve 是 Rust；不把 Go 代码迁成 Rust，也不把 Rust 后端塞进 kstack 仓。
  • 不改线协议：*_SCHEMA_V1、/v1/... 路径、operationId、tag、proto 包名与 descriptor 字节保持原样。
  • 不合并已有仓：kbox / kcl / kpower / ksandbox / kstudio / kbuddy 各自独立，保持现有 workspace 与发布节奏。
  • 不迁客户端：CLI、Studio、Web、官网、dashboard、tutorial-agent、packages、plugins、TUI 与 third-party vendored 全部留在 aster。
  • 本轮不执行：未复制、未重命名、未删除任何仓库代码；所有动作待计划确认后按阶段执行。
